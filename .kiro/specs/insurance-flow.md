# 旅遊保險申請流程規格

## 概述

旅遊保險是本系統的核心特色流程之一，從 AI 主動推薦到用戶電子簽名生效，全程無需離開對話介面。後台由 `insurance` 帳號（統超保險經紀人）審核並發送正式保單。

---

## 完整流程（4 步）

```
步驟 1：AI 推薦旅遊景點
    用戶：「我想去日本旅行」
    AI 呼叫：find_tourist_attractions(destination="日本")
    → 展示景點卡片後，AI 主動詢問是否需要旅遊保險

步驟 2：收集保險資料 → 建立諮詢單
    AI 收集：目的地、出發日期、回程日期、投保人數
    AI 呼叫：submit_inquiry(goal="旅遊保險申請", ...)
    前端：跳出「🛡️ 旅遊保險申請表」彈窗
    用戶填寫：姓名、身分證字號、出生日期、手寫電子簽名（streamlit-drawable-canvas）
    送出後：諮詢單 status = "04待簽名"，`insurance` 後台可見

步驟 3：保險後台審核
    insurance 帳號登入 vendor_dashboard.py
    操作：查看申請單 → 編輯保單內容 → 點「發送保單確認 Email」
    系統：自動發送 Email 給用戶，附上保單詳情與簽名連結
    諮詢單 status = "05待後台確認"

步驟 4：用戶簽名確認 → 保單生效
    用戶：在前端「我的訂單」找到待簽名保單
    操作：手寫電子簽名（drawable canvas）→ 送出
    系統：status = "80已完成"，自動發送保單生效 Email
    insurance 後台可見最終簽名圖片
```

---

## 資料庫欄位

### pms_form_feedback（諮詢單）

| 欄位 | 說明 |
|------|------|
| `feedback_no` | 14 碼純數字，格式 `2607060000XXXX` |
| `goal` | `"旅遊保險申請"` |
| `status` | `04` = 待用戶簽名；`05` = 待後台確認；`80` = 已完成；`90` = 已拒絕 |
| `name` | 姓名（AES-256-GCM 加密） |
| `contact_phone` | 電話（AES-256-GCM 加密，另存 SHA-256 雜湊） |
| `address` | 地址（AES-256-GCM 加密） |
| `signature_data` | Base64 簽名圖片（用戶簽名後儲存） |
| `insurance_doc` | 保單 JSON（後台編輯後儲存） |
| `note` | 目的地、日期、人數等補充資訊 |

---

## 前端 UI 要點

- **無電話欄位**：保險申請表不要求電話（避免個資過度收集）
- **電子簽名**：使用 `streamlit-drawable-canvas`，用戶手寫後轉 Base64 儲存
- **簽名狀態提示**：訂單列表中 status=04 的保單會顯示「待簽名」橘色標籤
- **雙簽名設計**：申請時簽一次（確認申請），後台發保單後再簽一次（確認生效）

---

## Email 觸發點

| 時機 | 收件人 | 內容 |
|------|--------|------|
| 用戶送出申請表 | 用戶 | 收到保險申請確認，告知審核中 |
| 後台發送保單 | 用戶 | 保單詳情 + 請至系統完成電子簽名 |
| 用戶完成最終簽名 | 用戶 + insurance | 保單正式生效通知（含簽名圖片） |

---

## 安全性

- 所有個資欄位（姓名/電話/地址）寫入 DB 前以 AES-256-GCM 加密
- `insurance` 後台讀取時自動解密顯示
- 簽名圖片以 Base64 儲存於 `signature_data` 欄位，不存放於檔案系統
- 後台帳號 `insurance` 只能看到 `goal = "旅遊保險申請"` 的諮詢單

## 相關工具
